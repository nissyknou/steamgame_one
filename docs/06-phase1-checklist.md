# STEP 0 — 環境の準備（1回だけ・約1時間）

## 0-1. Godot をインストールする

- [ ] [godotengine.org/download](https://godotengine.org/download) から **Godot 4.7.1** を入手
- [ ] **「.NET 版」ではない通常版**を選ぶ（本作は GDScript のため）
- [ ] インストール不要。ダウンロードした実行ファイルを好きな場所に置くだけ

> 例: `C:\tools\godot\godot.exe` / `/Applications/Godot.app` / `~/apps/godot`

## 0-2. コマンドラインから `godot` を使えるようにする

エージェントは作業開始時に `godot --version` を実行して環境を判定する。
**PATH が通っていないと、検証をスキップして「確認できていません」と返してくる。**

| OS | 手順 |
|---|---|
| **Windows** | 実行ファイルを `godot.exe` にリネーム → 置いたフォルダを 環境変数 `Path` に追加 → **ターミナルを開き直す** |
| **macOS** | `sudo ln -s /Applications/Godot.app/Contents/MacOS/Godot /usr/local/bin/godot` |
| **Linux** | 実行ファイルを `~/.local/bin/godot` に置いて `chmod +x ~/.local/bin/godot` |

- [ ] 新しいターミナルを開いて確認する

```bash
godot --version
```

- [ ] `4.7.1.stable...` のように表示されれば成功

> ❌ 「コマンドが見つかりません」→ PATH が通っていない。ターミナルを開き直したか確認。
> Windows は特に、設定後にターミナルを再起動しないと反映されない。

# STEP 1 — 画面を見る（最重要・最初のサイクル）

> **目的はただ1つ。「320×360 の左右分割が、想像どおりか」を自分の目で確かめること。**
> ここで違和感があれば、まだ何も作っていないので**安く作り直せる**。

## 1-1. Claude Code を起動する

```bash
cd steamgame_one
claude
```

- [ ] 起動したら、まず `/agents` でエージェント3体が見えるか確認（見えなくても動く）

## 1-2. 最初の指示を出す（コピペ）

```
CLAUDE.md、docs/GDD.md、docs/specs/coop-mechanic.md を読んで、
フェーズ1のステップ1を gameplay-engineer に実装させてください。

実装範囲は以下だけ。これ以上は作らないこと。
1. Godot プロジェクトの雛形（project.godot、ディレクトリ構成、signal_bus autoload）
2. 左右分割の SubViewport 構成（1サイド 320x360px、NEAREST フィルタ、整数倍スケール）
3. グリッド移動のプレイヤー2体（1マス16px）
4. 入力マップ（ゲームパッド2本 / キーボード分割の両方）
5. 位置関係が分かる程度の無地のグレーボックス床と壁

絵・音・テキスト・パズルの仕掛けはまだ作らないでください。
実装後、私が Godot で実行して確認するので、確認手順も教えてください。
```

- [ ] 実装が終わるまで待つ（数分〜十数分）
- [ ] 返ってきた「**確認すべき項目**」のチェックリストを読む

## 1-3. Godot でプロジェクトを開く

初回だけ手順が特殊。

- [ ] Godot を起動する（プロジェクトマネージャが開く）
- [ ] **「インポート」** をクリック
- [ ] クローンしたフォルダの中の **`src/project.godot`** を選ぶ
- [ ] 「インポートして編集」をクリック

> ❌ `project.godot` が見つからない → まだ作られていない。Claude Code に戻って
> 「project.godot が作られていません」と伝える。

## 1-4. 実行する

- [ ] **F5** キー（または右上の ▶ ボタン）を押す
- [ ] 初回は「メインシーンを選択」を聞かれることがある → 指示されたシーンを選ぶ

## 1-5. ★ 見て、判断する ★

**ここがあなたの本番。** 以下を1つずつ確認する。

### 見た目
- [ ] 画面が**左右に2分割**されている
- [ ] 左右それぞれに**キャラクターが1体ずつ**いる
- [ ] ドットが**にじんでいない**（ぼやけていたら NEAREST フィルタか整数倍スケールの問題）
- [ ] ウィンドウをリサイズしても崩れない

### 判断（★これが目的★）
- [ ] **1サイドの広さは、パズルの部屋として十分か？** 狭すぎないか
- [ ] **1マス16pxで、キャラと床と壁が見分けられるか？**
- [ ] **分割線を挟んで、両側を同時に把握できるか？** 目が疲れないか
- [ ] 左右分割で違和感はないか（上下分割のほうが良さそうに感じないか）

### 操作
- [ ] キーボードで**2体が別々に**動く（WASD と 方向キー）
- [ ] ゲームパッドがあれば、2本挿して両方動くか
- [ ] グリッド移動の速さは**もっさりしていないか**、逆に速すぎないか

## 1-6. フィードバックを返す

感じたことをそのまま Claude Code に言う。専門用語は不要。

```
実行しました。以下が気になります。
- 1サイドが思ったより狭い。部屋として窮屈に感じる
- グリッド移動が少しもっさりする
- ドットは綺麗に出ている
```

**遠慮なく違和感を言うこと。** ここで直すのが一番安い。

### 判断が割れたときの目安

| 感じたこと | 変更候補 |
|---|---|
| 狭い | 論理解像度を上げる（320×360 → 400×450）／マス目を 16px → 12px |
| キャラが小さくて見えない | マス目を 16px → 24px（部屋は狭くなる） |
| もっさりする | 1マスの移動時間を短くする（0.15秒 → 0.10秒） |
| 左右分割が窮屈 | **上下分割 ＋ 横視点**に戻す。ここが最後の引き返し地点 |

# STEP 2 — 交差リンクを入れる

> 「片方のボタンで、相手側のドアが動く」を実際に体験する。

## 2-1. 指示（コピペ）

```
ステップ1の確認が済みました。次に交差リンクを実装させてください。
docs/specs/coop-mechanic.md §3 のとおり、
Toggle / Hold / Momentary の3種の発信器と、ドア・可動足場の受信器を実装。
発信器は必ず signal_bus 経由で、link_id で対応づけること。

動作確認用に、1部屋だけ作ってください：
- 左側にスイッチ、右側にそのスイッチで開くドア
- 右側にスイッチ、左側にそのスイッチで開くドア
```

## 2-2. 確認

- [ ] 左のスイッチを押すと、**右のドア**が開く（左は何も起きない）
- [ ] 右のスイッチを押すと、**左のドア**が開く
- [ ] `Hold` を押している間、**その側のキャラが動けない**（★これが最重要）
- [ ] `Hold` を離すとドアが閉じる

> **`Hold` の体験を必ず自分で確かめること。** これが本作の会話を生む主要な仕掛け
> （`coop-mechanic.md` §4-bis T1）。「相手のために自分が足を止める」感覚があるか。

- [ ] コミット & プッシュ

# STEP 3 — 検証用の3室を作る

## 3-1. 指示（コピペ）

```
交差リンクの確認が済みました。次に検証用の3室を実装させてください。
docs/specs/coop-mechanic.md §4-3 のとおり：

第1室: 自己解決率 50%、技法なし
第2室: 自己解決率 10%、T1（Hold 拘束）を使う
第3室: 自己解決率 0%、T1 + T2（暗号と解読表の分離）を使う

3室を順に通しでプレイできるようにしてください。
グレーボックスのままでよく、絵・音・ストーリーは作らないこと。
```

## 3-2. 確認

- [ ] 3室を最初から最後まで通してプレイできる
- [ ] 部屋ごとに難しさ・依存度が上がっている実感がある
- [ ] **どこかで詰まって進めなくなる箇所がない**（解けない部屋は失敗）

## 3-3. 自分で一度、通しで解いてみる

- [ ] コントローラ2本を持って（または手を交互に使って）1人で解けることを確認

> ⚠️ **これは動作確認であって、プレイテストではない。** 会話が発生しないため、
> 本作の品質は測れない。次の STEP 4 が本番。

- [ ] コミット & プッシュ

# STEP 4 — ★プレイテスト（フェーズ1の本番）★

> **ここがフェーズ1の目的そのもの。** 3室を作ったのは、この30分のためだけ。

## 4-1. 準備

- [ ] **友達を1人呼ぶ**（ゲームに詳しくない人でもよい。むしろ多様なほうがよい）
- [ ] コントローラ2本（なければキーボード分割）
- [ ] **録音の準備**（スマホのボイスメモで十分）
- [ ] **録音してよいか許可を取る**。「あとで何を喋ったか数えたい」と正直に説明する
- [ ] 紙とペン（あなたが観察メモを取る）

## 4-2. 実施

- [ ] ゲームを起動して、**操作方法だけ**を説明する
- [ ] 録音を開始する
- [ ] **★ 遊んでいる間、あなたは一切喋らない ★**

> これが最も難しく、最も重要なルール。
> 詰まっているとヒントを出したくなるが、**絶対に我慢する**。
> ヒントを出した瞬間、そのデータは無効になる。
> 本当に完全に行き詰まったときだけ、「ここは飛ばしましょう」と言って次へ進む。

- [ ] 観察メモを取る（下記）

### 観察するポイント

| 見るもの | メモ例 |
|---|---|
| **どこで黙ったか** | 「第2室で40秒無言」← 悪い兆候か、集中か |
| **どこで盛り上がったか** | 「ドアが開いた瞬間に2人とも声を上げた」 |
| **何を喋ったか** | 「押して」だけか、状況を説明していたか |
| どこで詰まったか | 「第3室の暗号の意味が伝わらなかった」 |
| 画面のどこを見ていたか | 自分の側だけか、相手側も見ていたか |
| 途中で飽きた素振り | 姿勢、スマホを触る等 |

## 4-3. 終わった直後に聞くこと

**「面白かった？」から聞かない。**（気を遣って「面白かった」と言われるだけ）

- [ ] 「**何が一番印象に残った？**」
- [ ] 「どこが一番わけがわからなかった？」
- [ ] 「相手に何を伝えようとしていた？」
- [ ] （相手にも）「これ、他の友達とやりたいと思う？」

- [ ] 録音を止め、メモを清書する

## 4-4. できれば2〜3組でやる

- [ ] 1組だけだと、その2人の相性の影響が大きい。可能なら別の組でも試す

# STEP 5 — 判定する

## 5-1. 集計させる

```
プレイテストの録音を書き起こしました（または要点をメモしました）。
qa-engineer に発話を4分類（指示 / 状況説明 / 合意形成 / 感情）させて、
部屋ごとに集計し、仮説 H1 と H2 の成否を数値で判定させてください。
結果は docs/qa/ に残してください。
```

- [ ] 書き起こしまたはメモを渡す（完璧な書き起こしでなくてよい。要点で十分）

## 5-2. 合格ラインを確認する

| 判定 | 基準 |
|---|---|
| **H1** | 自己解決率が下がるほど、発話量が増えたか |
| **H2** | 自己解決率 0% の第3室でも、会話が「押して／押した」に痩せなかったか |
| **合格ライン** | **「状況説明」＋「合意形成」が全発話の 3割超** |

## 5-3. 結果によって進む道が変わる

```
合格（3割超）
   └→ フェーズ2へ。全10〜12室のグレーボックスを作る

不合格だが惜しい（2〜3割）
   └→ 技法を足す（T3〜T5）／自己解決率の下限を 10〜20% に見直す
      → 3室を修正して、もう一度プレイテスト

明確に不合格（1割台、または「押して／押した」だけ）
   └→ H2 棄却。設計を見直す
      → メイン会話と game-design-reviewer で、
         協力の作り方そのものを再検討する

そもそも解けない・つまらない
   └→ 企画ごと見直す。ここで気づけたなら大成功
      （3室しか作っていないので、捨てても安い）
```

> **不合格は失敗ではない。** 3室で気づくために、この工程がある。
> 12室作ってから気づくほうがはるかに高くつく。

# 絶対にやってはいけないこと

| ❌ | なぜ |
|---|---|
| 絵・音・テキストを作り始める | 仮説が棄却されたら全部捨てることになる |
| 3室より多く作る | 同上。検証に必要な最小量が3室 |
| プレイテスト中にヒントを出す | そのデータが無効になる |
| 1人でプレイして「プレイテストした」ことにする | 会話が発生せず、本作の品質が測れない |
| 部屋を「面白くしよう」として仕掛けを増やす | スコープクリープの始まり。`game-design-reviewer` に相談する |
| Godot のバージョンを上げる | シーン形式が変わることがある |
| ステップ1の目視確認を飛ばす | 12室作った後に「狭すぎる」と気づくことになる |
