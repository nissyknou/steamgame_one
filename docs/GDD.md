## 1. 一行で言うと

> **疎遠になった二人の友人が、共有した記憶を新しい順に遡っていく、2人協力必須のパズルゲーム。**
> 遡るほどに、二人は互いを必要とするようになる。

---

## 2. 目指す体験（デザインゴール）

このゲームが成功したと言えるのは、**遊び終えた2人が、しばらく黙る**とき。

- 「面白かった」ではなく「**話したくなる**」で終わらせる
- プレイヤー2人の**実際の関係**に、ゲーム内の二人が重なるように設計する
- 感動を**カットシーンで説明しない**。プレイヤーの手の動きで思い出させる

### 中核となる設計原理：協力＝テーマ

**協力の必要度が、そのまま関係の濃さの表現になる。**

| 章 | 時代 | 協力の必要度 | 表現される関係 |
|---|---|---|---|
| 1 | 現在（30代） | **低** — 半分は一人でも進める | 疎遠。互いを頼らない |
| 2 | 20代 | 中 | 進路が分かれ、距離ができ始める |
| 3 | 高校 | 高 | 最も一緒にいた時期 |
| 4 | 出会った日（子供） | **最高** — 1歩も一人では進めない | 完全な相互依存 |

通常のゲームは難易度が上がるが、このゲームは**協力の密度が上がる**。
プレイヤーは章を追うごとに「相方と喋る量が増えていく」自分に気づく。
そしてそれは、二人が近づいていくことと同義になっている。

> ここが本作の全て。**この一致が壊れる変更は、どんなに面白くても却下する。**

## 3. コアループ

```
① 部屋（1画面のパズル空間）に入る
      ↓
② 二人が別々のものにしか触れないことに気づく
      ↓
③ 声で状況を伝え合い、手順を組み立てる
      ↓
④ 同時／順番に操作して仕掛けを解く
      ↓
⑤ 次の部屋へ。断片的な記憶が1つ再生される
      ↓
   （章の終わりで時代が1つ遡る）→ ①へ
```

**1部屋 = 2〜5分。** テキストは短く、パズルの合間に置く。

---

## 4. 協力メカニクスの核

### 4-1. 「触れられるものが違う」

同一画面・同一空間。**二人とも全部見えているが、触れるものが違う。**

| | プレイヤー1 | プレイヤー2 |
|---|---|---|
| 呼称（仮） | **残った側** | **去った側** |
| 触れるもの | **いま在るもの** — 扉、箱、スイッチ、明かり | **かつて在ったもの** — 消えた足場、昔の張り紙、無くなった木 |
| 見え方 | 実体（不透明） | 残像（半透明・別パレット） |

- P1 が「ここ、壁で行き止まり」と言う
- P2 には、そこに**昔あった扉**の残像が見えている
- P2 が残像の扉を開けると、P1 の側の壁に通り道が生まれる

**「見えているのに、自分では手が届かない」** — これが友情のメタファーであり、
同時に会話を強制するパズル機構になっている。

> ⚠️ この設計は Steam Remote Play Together の制約から導かれている。
> RPT はホスト画面をそのまま配信するため「相手にだけ見える情報」は作れない。
> よって非対称性は**視覚**ではなく**干渉可能性**に置いた。詳細は `CLAUDE.md` §2。

### 4-2. 「合図」— 本作唯一の特殊アクション

言葉以外の、二人だけの通信手段。ボタン1つで自キャラが短い動作をする。

- 章1では、ただの無意味なエモート（プレイヤーは意味を知らない）
- 章を遡るごとに、合図が使われる場面が現れる
- **章4（出会った日）で、二人がこの合図を作る瞬間が描かれる**
- そして**最終場面**で、テキストもUI表示も一切ない部屋が1つだけ残る
  → プレイヤー2人は、ゲームを通して身体で覚えた合図だけで、それを解く

**プレイヤー自身の学習が、キャラクターの記憶と重なる。**
これが「心に何かを残す」ための唯一にして最大の仕掛け。

### 4-3. 意図的に入れないもの

- 死亡・失敗・ゲームオーバー（**緊張は感情の邪魔になる**）
- タイムリミット、スコア、ランキング
- 戦闘、敵
- インベントリ、育成、リソース管理

## 5. 物語

### 5-1. 構造：時間を遡る4章

| 章 | 時代 | 場所（案） | 明かされること |
|---|---|---|---|
| 1 | 現在 | 取り壊し前の建物 | 二人は久しぶりに会った。会話が少ない |
| 2 | 十数年前 | 駅、下宿 | 片方が街を出た。見送りがあった |
| 3 | 高校 | 校舎、屋上、帰り道 | 最も一緒にいた時期。何かの約束をした |
| 4 | 子供時代 | 空き地、秘密基地 | 出会った日。**合図が生まれる** |
| — | 現在（回帰） | 章1と同じ場所 | 最後の1部屋。合図だけで解く |

### 5-2. 語り口

- **説明しない。** 部屋に残った物、書き置き、消えた家具で語る
- セリフは短く、少なく。**沈黙を演出として使う**
- 「なぜ疎遠になったか」に**明確な事件を置かない**。
  ほとんどの友情は、事件ではなく**ただ時間で薄れる**。そのほうが刺さる
- 名前は与えるが、性別・容姿は最小限に留め、プレイヤー2人が自分を重ねられるようにする

### 5-3. 結末の方針

再会してやり直す/やり直さない、を**断定しない**。
最後の合図が通じた、という事実だけを残して終える。
考えを巡らせる余地を残すことが、本作の目的そのもの。

## 6. スコープ定義（v1.0 の完成条件）

これを満たしたらリリースする。**これ以上は作らない。**

| 項目 | 分量 |
|---|---|
| 章 | 4章 + 終幕 |
| パズル部屋 | **合計 14〜16室**（章あたり 3〜4室 + 終幕 1室） |
| プレイ時間 | 1〜2時間 |
| プレイアブルキャラ | 2体 × 4年代（同一スプライトのサイズ・色差分で実装） |
| 背景ロケーション | 章あたり 1〜2、合計 6箇所程度 |
| BGM | 5曲（章ごと + 終幕） |
| SE | 20〜25種 |
| テキスト量 | 日本語 4,000〜6,000字程度 + 英訳 |
| 対応言語 | 日本語・英語 |
| Steam機能 | 実績（10個程度）、Remote Play Together 対応、クラウドセーブ |

### やらないこと（v1 対象外 = 将来検討行き）

`CLAUDE.md` §3 のリストを参照。特に **オンラインネットコードは絶対に作らない**。

## 7. ターゲットと市場

- **主対象**: 友人と一緒に短時間で遊べる体験を探している人。
  *It Takes Two* / *We Were Here* / *Unravel Two* を遊んだ層
- **副次**: *To the Moon* / *Undertale* / *OMORI* のような「物語が刺さる」ゲームを好む層
- **売り方の軸**: 「2時間で終わる」ことを弱点ではなく**強み**として打ち出す
  （友達と時間を合わせられる長さ）
- 価格帯: 未定（フェーズ4で `marketing-researcher` が調査）

## 8. フェーズ計画

| フェーズ | ゴール | 完了条件 |
|---|---|---|
| **0** ✅ | 企画確定 | 本GDD と `CLAUDE.md` |
| **1** | **面白さの検証** | 部屋 **3室だけ**の縦切りプロトタイプ。2人で遊んで「喋りたくなる」か |
| 2 | 全体構造の実装 | 全14〜16室の**グレーボックス**（絵と音なし）で通しプレイ可能 |
| 3 | 見た目と音 | アート・BGM/SE・UI・テキスト確定 |
| 4 | リリース | Steamページ、審査、Coming Soon、発売 |

> **フェーズ1が最重要。** ここで「2人が喋らない」なら、企画ごと作り直す。
> 絵も音も物語も、コアが検証されるまで一切作らない。

## 9. 未決定事項（差し替え可能）

以下は v0.1 時点の仮置き。ユーザーの判断で変更してよい。

1. **タイトル** — 『合図』/ *Signal* は仮。Steam に同名多数のため要再検討
2. **二人の設定** — 性別、名前、関係の細部（幼馴染か、転校生か等）
3. **舞台の時代・地域** — 日本を明示するか、無国籍にするか
4. **章1で「なぜ再会したか」の理由** — 建物の取り壊し？ 誰かの死？ 同窓会？
5. **視点** — 見下ろし型（トップダウン）か、横視点か
6. **「合図」の具体的な動作** — ジャンプ？ 手を振る？ 音を鳴らす？
7. **アートの限定パレット** — 色数と方向性（`art-director` がフェーズ3で提案）
