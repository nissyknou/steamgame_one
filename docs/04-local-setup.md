# ローカル開発環境のセットアップ（引き継ぎ手順）

フェーズ0（企画）はクラウド上の Claude Code セッションで行った。
フェーズ1以降は **Godot が動くローカルマシンで作業する**（2026-08-16 決定）。

理由: プロトタイプの目的は「**実際に2人で遊んで喋るか**」の検証であり、
描画・操作感・協調プレイは実行しないと判断できないため。

---

## 1. 必要なもの

| | 内容 |
|---|---|
| **Godot** | **4.7.1**（2026-08 時点の最新安定版）。**.NET 版ではなく通常版**を使う（GDScript のため） |
| Git | — |
| Claude Code | ローカルマシンにインストール |
| コントローラ | できれば2本。なければキーボード分割で代用可 |
| **2台目のPC** | **不要**（ローカル協力のため1台で2人プレイできる） |

Godot はインストール不要の単一実行ファイル。
[godotengine.org/download](https://godotengine.org/download) から入手する。

### バージョンを固定する理由

Godot はマイナーバージョン間でシーンファイルの形式が変わることがある。
**プロジェクトを開いたバージョンを `.godot-version` に記録し、勝手に上げない。**
上げるときは意図的に、動作確認とセットで行う。

## 2. 手順

```bash
git clone https://github.com/nissyknou/steamgame_one.git
cd steamgame_one
```

**既定ブランチが `claude/steam-game-dev-roles-9t3ped` になっている**ため、
クローンした時点で全ドキュメントが揃っている。

### コマンドラインから Godot を使えるようにする

エージェント（`gameplay-engineer` / `qa-engineer`）は、作業開始時に
`godot --version` を実行して環境を判定する。**PATH を通しておくこと。**

| OS | 例 |
|---|---|
| Windows | 実行ファイルを `godot.exe` にリネームし、置いたフォルダを PATH に追加 |
| macOS | `ln -s /Applications/Godot.app/Contents/MacOS/Godot /usr/local/bin/godot` |
| Linux | 実行ファイルを `~/.local/bin/godot` に配置 |

確認:
```bash
godot --version          # 4.7.1.stable のように表示されればOK
godot --headless --quit  # プロジェクト内で実行し、エラーなく終了すればOK
```

PATH を通さない場合、エージェントは「Godot が使えない」と判定して動作確認を行わず、
すべてを「ユーザーの手元での確認が必要」として返す（誤った成功報告を防ぐため）。

## 4. ローカルで最初にやること

`docs/specs/coop-mechanic.md` §9 がフェーズ1の完了条件。
ただし**一度に全部作らない**。次の順で、都度目視確認を挟む。

### ステップ1：画面を見る（最優先）

1. Godot プロジェクトの雛形（`project.godot`、ディレクトリ構成、`signal_bus` autoload）
2. 左右分割の `SubViewport` 構成（1サイド 320×360 px）
3. グリッド移動のプレイヤー2体、入力マップ（パッド2本 / キーボード分割）

ここで **必ず一度エディタで実行し、自分の目で見る。**

> **判断すべきこと**: 320×360 の左右分割は、想像どおりの見え方か。
> 狭すぎないか。1マス16pxでキャラと仕掛けが読み取れるか。
> **これは実行しないと絶対に判断できない。** ここで違和感があれば、
> 論理解像度・マス目サイズ・分割方向を作り直す。**まだ安い段階のうちに。**

### ステップ2：交差リンク

4. `Toggle` / `Hold` / `Momentary` の3種（`coop-mechanic.md` §3-3）

`Hold` が最重要（§4-bis T1）。押している間その側は移動できない挙動を必ず入れる。

### ステップ3：検証用の3室

5. 自己解決率 **50% / 10% / 0%** の3室（§4-2, §4-3）

### ステップ4：プレイテスト（本番）

**誰かに来てもらって、2人で遊ぶ。** これがフェーズ1の目的そのもの。

- 遊んでいる間の**会話を録音する**（許可を取ること）
- `qa-engineer` に発話を4分類させ、集計させる
- **合格ライン: 「状況説明」＋「合意形成」が全発話の3割超**（GDD §8）

> ⚠️ 自分1人でコントローラ2つを持って試すのは、動作確認にはなるが
> **プレイテストにはならない。** 会話が発生しないため、本作の品質指標が測れない。
