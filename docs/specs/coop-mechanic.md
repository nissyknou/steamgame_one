# 仕様：協力メカニクス（分割画面 ＋ 交差操作）

対象: `gameplay-engineer`
親文書: [`docs/GDD.md`](../GDD.md) §4 / [`CLAUDE.md`](../../CLAUDE.md) §2
状態: **v0.2 — フェーズ1（縦切りプロトタイプ）向け**

---

## 1. 用語

| 用語 | 定義 |
|---|---|
| **サイド** | 分割画面の片側。`SIDE_A`（P1）/ `SIDE_B`（P2） |
| **部屋** | 1つのパズル単位。A側の空間と B側の空間の**ペア**で1部屋 |
| **合流点** | 章末に置く、分割が解けて二人が同じ空間に並ぶ場面 |
| **自己解決率** | 自分の行く手を塞ぐ障害のうち、自分側の操作で取り除ける割合 |
| **交差リンク** | 一方のサイドの発信器と、他方のサイドの受信器の対応づけ |
| **残像レイヤー** | より古い記憶を表す半透明の描画レイヤー（GDD §4-3） |

---

## 2. 画面構成

- 2分割。分割方向（左右／上下）は **GDD §9-6 で未決定**。
  → **プロトタイプでは切り替え可能に実装し、両方を試して決める**
- 各サイドは独立したビューポート・独立したカメラを持つ
- **互いのプレイヤーキャラは相手のサイドに描画されない**（別空間にいるため）
- 両サイドは常に同時に描画される。どちらかを隠す演出は行わない

### Godot 実装方針

- ルート: `SplitScreen`（`HBoxContainer` または `VBoxContainer`）
- 各サイド: `SubViewportContainer` > `SubViewport` > `World2D`
- **A側と B側は別の `World2D` を持つ**（物理・当たり判定を完全分離する）
- 交差リンクは World をまたぐため、**シグナルを中継する自動読み込みシングルトン**を経由する
  （直接ノード参照を持たせない。World が別なので参照が壊れやすい）

### ⚠️ RPT 制約（`CLAUDE.md` §2）

- 両プレイヤーは**同じ映像**を見る。分割しても情報は隠れない
- したがって **「相手にしか読めない／見えない情報」に依存する謎を作ってはならない**
- 非対称性は**干渉可能性**（触れられるか）のみに置く
- プレイヤーごとに異なる UI スケール・解像度は持てない

## 3. 交差操作

### 3-1. 原則

> **発信器の操作は、常に反対サイドの受信器にのみ作用する。**
> 自分のサイドには一切影響しない。

| 種別 | 例 | 配置 |
|---|---|---|
| 発信器 | スイッチ、レバー、押しボタン、重量板 | 押した側のサイド |
| 受信器 | ドア、可動足場、昇降機、明かり | **反対**のサイド |

### 3-2. データ構造

交差リンクは `link_id`（文字列）で対応づける。

```gdscript
# 発信器: 押されたら link_id を発報するだけ。相手を知らない
signal_bus.emit_link(link_id: String, value: bool)

# 受信器: 自分の link_id を購読する
signal_bus.link_changed.connect(_on_link_changed)
```

- **発信器は受信器を直接参照しない。** 必ず `signal_bus` を経由する
- 同じ `link_id` を持つ受信器が複数あってよい（1つの発信器で複数の扉が動く）
- `link_id` は部屋スコープで一意。命名: `ch1_r2_door_north`

### 3-3. 発信器の種類（プロトタイプではこの3つだけ）

| 種類 | 挙動 | 用途 |
|---|---|---|
| `Toggle` | 押すたびに ON/OFF が反転。状態を保持 | 基本 |
| `Hold` | 押している間だけ ON。離すと OFF | **相手が動く間、自分は動けない**状況を作る |
| `Momentary` | 押した瞬間に1回だけ発報 | 順序パズル |

`Hold` が本作で最も重要。「相手のために自分が足を止める」という体験を直接作る。

### 3-4. 禁止事項

- 自サイドに作用する発信器を作らない（原則が濁る）
- タイミングがシビアな同時押しを**プロトタイプでは作らない**
  → 音声通話の遅延（RPT 経由）で理不尽になる。許容誤差は最低 0.5 秒

## 4. 自己解決率

GDD §2 の数値を、部屋単位で実装可能な形にする。

### 4-1. 定義

```
自己解決率 = (自サイドの操作だけで取り除ける障害の数) / (自サイドの障害の総数)
```

### 4-2. 章ごとの目標値

| 章 | 目標 | 実装イメージ（1サイドに障害4つの場合） |
|---|---|---|
| 1 | 約 50% | 自分で開けられる扉2 + 相手依存の扉2 |
| 2 | 約 30% | 自分1 + 相手3 |
| 3 | 約 10% | 自分0〜1 + 相手3〜4 |
| 4 | **0%** | 自分0 + 相手4 |
| 終幕 | 0% + 言葉なし | 合図のみで解く |

### 4-3. プロトタイプでの割り当て

フェーズ1の3室は、**H1 / H2 の検証のために**次の値で作る（GDD §8）。

| 室 | 自己解決率 | 検証したいこと |
|---|---|---|
| 1 | 50% | 交差操作の学習が成立するか |
| 2 | 10% | 発話量が増えるか（H1） |
| 3 | **0%** | 会話が痩せないか（**H2**） |

## 5. 残像レイヤー（過去の滲み出し）

- 各サイドの `World2D` に、通常レイヤーと**残像レイヤー**を持つ
- 残像は半透明・別パレット。**両プレイヤーに見える**（隠された情報ではない）
- 章が進むほど残像の**画面占有率**を上げる（GDD §2 の表）
- **残像には干渉できない。** 見えるだけ
  → 終幕でのみ実体化し、干渉可能になる

> ⚠️ v0.1 にあった「P2 だけが残像に触れる」設計は **v0.2 で廃止**。
> 交差操作（§3）が非対称性を担うため、残像は純粋に演出となった。

**プロトタイプでは実装しない。** フェーズ2以降。

## 6. 合図

- 入力: 専用ボタン1つ
- 挙動: 自キャラが短いモーションを再生する
- **反対サイドの画面端に、合図が届いたことを示す小さな反応を表示する**
  （分割の向こうにも届く、と分かることが重要）
- 終幕でのみ、合図がパズルの解法そのものになる

**プロトタイプでは「押すとモーションが出て、相手側に反応が出る」だけ実装する。**
意味付けはフェーズ2以降。

## 7. 入力

`CLAUDE.md` §2 のとおり、次の両方に対応する。

| 構成 | P1 | P2 |
|---|---|---|
| コントローラ2本 | ゲームパッド1 | ゲームパッド2 |
| キーボード分割 | WASD + F | 方向キー + テンキー0 |

- Godot の `InputMap` でアクションを `p1_*` / `p2_*` に分ける
- **ホットプラグに対応する**（RPT では相手のパッドが後から接続される）
- ポーズは**どちらからでも**可能にする

---

## 8. 意図的に実装しないもの

GDD §4-5 と `CLAUDE.md` §3 に加えて、本メカニクス固有:

- プレイヤー同士の当たり判定・押し合い（別空間にいるため不要）
- 一方だけがゲームオーバーになる状態
- 3分割以上、動的な分割数変更
- 隠された情報に依存する仕掛け（RPT で成立しない）

---

## 9. フェーズ1の完了条件

1. 分割画面で2人が別々に動ける（コントローラ2本 / キーボード分割の両方）
2. 交差リンクが動作する（`Toggle` / `Hold` / `Momentary` の3種）
3. 自己解決率 50% / 10% / 0% の3室を通しでプレイできる
4. 合図ボタンが両サイドに反応を出す
5. **2人でプレイし、発話を記録できる**（`docs/qa/` に記録を残す）

> グレーボックスでよい。**絵・音・テキストは一切作らない。**
> このフェーズの目的は「解けること」ではなく「**喋ること**」の検証。
